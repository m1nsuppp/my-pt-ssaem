# Commit Guidelines

커밋은 다음 조건을 **모두** 충족할 때만 실행한다. 하나라도 실패하면 커밋하지 말고 먼저 해결한다.

## 커밋 조건 (모두 충족 시에만)

1. **모든 테스트가 통과** — 관련 테스트뿐 아니라 전체 스위트가 통과해야 한다. 실패한 테스트가 있으면 커밋 금지.
2. **모든 컴파일러/린터 경고가 해결됨** — 새 경고를 도입하지 않았는지 확인. 경고가 남으면 커밋 금지.
3. **변경이 하나의 논리적 작업 단위를 구성** — 한 커밋에 서로 무관한 변경을 섞지 않는다. 단일 목적·단일 관심사로 묶인다.
4. **커밋 메시지가 구조적(structural) 변경인지 행동적(behavioral) 변경인지 명확히 표기**
5. **작고 빈번한 커밋 선호** — 크고 드문 커밋보다 작고 자주 나누는 커밋이 낫다. 작업이 여러 단위로 쪼개지면 각각을 별도 커밋으로 분리한다.

## 커밋 메시지 컨벤션

```text
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

한국어로 작성합니다.
